# Forge: executable tasks

Здесь находятся согласованные задачи из [UI-плана](../docs/UI_IMPLEMENTATION_PLAN.md).
Backend M0–M3 сохраняют прежние ledgers; новая нумерация их не заменяет.

Начинайте с [INDEX.md](INDEX.md): он показывает статус, зависимости и ближайший
шаг. Затем прочитайте Task, указанный epic и относящиеся к работе правила из
[PROJECT_RULES](../docs/PROJECT_RULES.md). PRD и domain-model документы остаются
источниками доменного смысла.

## Как выполнять

- Один файл — один ограниченный результат, с scope, non-goals и проверкой.
- `in_progress` не означает закрытую Task; `done` требует записанного evidence.
- Проверяйте dependencies до изменений. Независимые эпики не гарантируют
  безопасность одновременных правок одного файла, lockfile или dev-сервера.
- После выполнения обновляйте статус в Task и INDEX, фактические проверки,
  ограничения и ссылки на оставшуюся работу. Не считайте целый epic закрытым
  по одному завершённому шагу.
- Не создавайте пустые будущие Task. Их IDs и границы появляются при отдельной
  нарезке; пока индекс может ссылаться на ещё не нарезанные эпики.

Execution prompt должен называть файл Task, разрешённые области изменений,
выходной результат, ограничения ресурсов и проверочные команды. Live provider
Runs всегда требуют отдельного разрешения, даже если выполняется UI-задача.
