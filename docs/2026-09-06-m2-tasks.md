## First independent implementation tasks

### Employee management (TASK-26 foundation)

adapter, storage employee/scheduler paths, migration
`0015_m2_employee_management.sql`, command and capacity integration tests.

Write negative revision/capacity/lifecycle tests; implement immutable Run profile

replace both scheduler admission checks and the physical Employee uniqueness
index. Retain Task/surface writer uniqueness and physical-release requirements.
Run domain/application/conformance tests, then storage-backed concurrency tests.

### Git backend (TASK-24 foundation)

Files: `forge-domain/src/git*`, `forge-supervisor/src/git*` and isolated Git tests.
Define validated IDs/ref/path and candidate/intent types. Implement bounded Git
inspection, snapshot, exact merge preparation, CAS and recovery. Test dirty
candidate, checked-out branches, stale target, retry and ambiguous recovery.
Backend completion does not imply Core Integration wiring is complete.

### Claude adapter (TASK-20)

Files: new `crates/forge-provider-claude`, workspace manifest and lockfile.
Implement pinned preparation, isolated subscription credential input, stream
messages/ACK parsing and normalized evidence. Add fake-CLI contract fixtures and
test malformed events/secret redaction. Live usage remains explicitly opt-in.
Crate completion does not imply Supervisor enrollment/integration is complete.

### Inbox and assignment contracts (M2.4 foundation)

Files: new domain communication/assignment modules, application Inbox commands,
storage Inbox repository, migration `0016_m2_inbox.sql`, boundary tests.
Implement task-optional threads, immutable messages, explicit targets and receipt
requirements. Verify cross-Project, wrong Employee/context, duplicate, late ACK
and completion-watermark behavior before connecting runtime delivery.

## Final review notes

Independent implementation and documentation reviews were completed. Confirmed
correctness findings were fixed and rechecked, including linked command-receipt immutability,
admission queue fairness, required-Hook completion barriers, bounded Podman
diagnostics and stale Communication ownership documentation.
The aggregate run also exposed a test-only stack overflow in nested Git
scenario futures. Debugger inspection found no recursive dispatch; boxing the
three scenario phases fixed it on the default stack. A non-polling future-size
regression failed before the fix and passed afterward, as did all 20 Git cases.
The shared harness now resolves each created Pipeline from its command receipt,
not the first Pipeline in the Project; Hook/provider coexistence verifies this.

The shared development PostgreSQL later exhausted its default 62.5 MiB DSM
mount after hundreds of retained schemas, followed by a backend crash/recovery.
Its dev mount is now explicitly 512 MiB and aggregate service-backed suites run
sequentially. Only the container was recreated; its named volume and 640 existing
test schemas were preserved. Interrupted gates are not successful acceptance.
The final M0 smoke's existing `dev-up` also refreshed the other development
containers because their Compose configuration hash changed; all named volumes
were reused. PostgreSQL remained healthy through both sequential Rust suites.
An existing non-blocking `validate_schema` catalog lookup cost was noted for
future optimization; it is not established as the cause of the PostgreSQL crash.

The 500-effective-line review trigger was checked. Larger files retain cohesive
central command/protocol dispatch, storage port forwarding, durable journal or
runner coordination responsibilities; their feature-specific logic is split
into modules. The reference transaction adapter and Gateway acceptance suite
were reviewed as test infrastructure. The trigger is not a blanket file-size
exception for future changes and does not impose a function-size cap.

README guidance follows `crafting-effective-readmes`: setup, keyless verification
and explicitly paid live usage are separated, with focused operator guides linked
instead of embedding every contract in the project introduction.
