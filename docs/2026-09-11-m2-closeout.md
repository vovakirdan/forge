# M2: приёмка pin и файловых snapshots

Дата: 11 сентября 2026.
Статус: M2 закрыта по пересогласованным exit gates; provider live-приёмка отложена.

## Пересогласованная граница M2

По решению владельца authenticated provider gates не блокируют закрытие M2.
Они отложены, а не засчитаны как успешные. Реализация четырёх профилей и их
keyless contract tests остаются в M2; live-поддержка каждой lane требует
собственных evidence и отдельного разрешения расхода лимитов.

Полный Codex Git-сценарий уже принят по сохранённым live evidence, включая
stale-base rework и повторные review/QA. Это восстановленная assessment, не
новый запуск и не исправление исходного неуспешного exit launcher. Подробности —
в [журнале live-приёмки](2026-09-09-m2-live-workflow-specs.md).

Завершающие exit gates пройдены: keyless pin и snapshots с настоящими файловыми
и контейнерными границами, регрессия M0–M2 и независимое review.

## Что проверено

### Git pin

- Core передаёт новому writer точную pinned policy и её revision. Последующее
  изменение настройки Task не заменяет уже созданный RunSpec.
- Настоящий Git target уже находится на B, когда контейнер получает pin A.
  Проверяются descriptor, SHA-256 и ref реального bundle, а также рабочие файлы A.
- Изменение target не меняет export активного Run. Будущий `latest_target`
  получает B; новая поверхность начинается на B.
- Повторный Run на сохранённой поверхности не сбрасывает HEAD, index, staged,
  dirty и untracked файлы. Обновлённый bundle остаётся отдельным входом.
- Несовместимый pin удерживает Integration для решения менеджера: нет скрытого
  unpin или бесконечного автоматического rework.

### Файловые snapshots

- Named import/attach проходит через настоящие Core, PostgreSQL, gRPC,
  Supervisor и rootless Podman. `/run/forge-inputs/inputs.json` соответствует
  frozen RunSpec; текстовые, пустые и бинарные файлы сохраняют исходные байты
  после изменения оригиналов.
- Запись в snapshot внутри контейнера получает именно `Read-only file system`,
  а не отказ из-за chmod. В workspace нет overlay; явное копирование разрешено.
- Capture работающего контейнера отклоняется и не останавливает его. Named
  `PauseTask` переводит Task в waiting, Supervisor подтверждает физическую
  остановку; после этого настоящий capture запечатывает файлы в Artifact.
- Отдельный физический Supervisor-сценарий проверяет executable bit, создание
  нового файла в RO mount и immutable replay capture после изменения источника.
- Core/PG и safe-file tests проверяют чужой scope, unsafe paths, доступ к runtime
  и SecretStore, reservation и отсутствие гонки capture с writer/Integration.

Сквозной Core smoke использует InMemory object backend, а не MinIO. Реальный
MinIO проверен отдельным storage gate: binary/empty bytes и create-only replay.
Это два уровня проверки одной object-store границы, не единый end-to-end Run
с MinIO. Synthetic CLI выполняет только детерминированный fixture; модель,
логин и персональные credentials не используются.

## Проверки и воспроизведение

Запускать из корня Forge с существующим локальным dev environment:

```bash
CARGO_BUILD_JOBS=2 just build-runtime-fixture

bash -c '
  set -euo pipefail
  source scripts/lib/dev.sh
  require_dev_environment
  export CARGO_BUILD_JOBS=2 FORGE_INTEGRATION=1
  cargo test --locked -p forge-testkit --test command_conformance \
    --test m2_git_proposal source_policy -- --ignored --test-threads=1
  cargo test --locked -p forge-testkit --test m2_file_snapshots \
    --test m2_file_delivery -- --ignored --test-threads=1
  cargo test --locked -p forge-testkit --test m1_runtime \
    input_acceptance -- --ignored --test-threads=1
'

CARGO_BUILD_JOBS=2 cargo test --locked -p forge-supervisor --lib \
  podman_tests::input_acceptance -- --ignored --test-threads=1
CARGO_BUILD_JOBS=2 bash scripts/test-minio-bucket.sh --evidence
```

Общие gates: `CARGO_BUILD_JOBS=2 just test-m2`,
`CARGO_BUILD_JOBS=2 just test-integration`, workspace tests, fmt, strict Clippy
и `git diff --check`. Общие service-backed наборы выполняются последовательно.
Команды не запускают `test-m2-live`, `test-codex-live` или operator launcher.

Результаты этого прогона:

- Core source policy и snapshots: passed; отдельный новый pinned-writer test
  также passed. Сквозной Core/Podman snapshot test: passed.
- Два физических Supervisor input tests: passed; финальная версия повторно
  прошла общий integration gate.
- MinIO: 2 passed.
- `scripts/test-m2.sh`: passed, 266 Rust checks плюс shell-сценарии. Этот запуск
  предшествует компиляции нового pinned-writer test; он проверен отдельно.
- Workspace strict Clippy: passed.
- Workspace tests: 544 passed; fmt и `git diff --check`: passed.
- `scripts/test-integration.sh`: exit 0, 186 Rust checks, включая 14 настоящих
  Podman tests, и завершающий native M0 CLI smoke: Task `done`, 1 Run,
  1 Artifact, 15 Events. Повторно прошли новые physical и Core input tests.
- Независимое RO-review и ручная проверка простоты: confirmed findings нет.
  Большой Supervisor test module прошёл review по правилу 500 эффективных строк:
  два связанных сценария и локальные helpers, без нового framework/dependency.

Локальные логи: `/tmp/forge-m2-closeout.CbBpzIqA/`; `input-code.sha256` фиксирует
проверенные тесты и synthetic CLI, `fixture-image.digest` — образ. Они относятся к текущей
рабочей копии, не к новому коммиту; временные каталоги могут быть очищены ОС.
Прежние playground, Git target и provider evidence не изменяли. Временный
MinIO test bucket удалён штатным cleanup; новых платных Runs не было.
После прогонов нет работающих тестовых контейнеров; четыре исходных dev-сервиса
сохранили идентификаторы и uptime. `podman-compose` при финальном `dev-up`
напечатал `name already in use`, затем успешно использовал существующие сервисы;
это не ошибка теста или замена контейнеров.

M0 smoke сохранил `/tmp/forge-m0-runtime.X4TRI2` и отдельную БД
`forge_m0_1b28167cb8d42424ed4a100e2ebf9976`. Commit/push не выполнялись.

## Отложенная проверка провайдеров

Четыре коротких authenticated live gates и отдельная Claude MCP/artifact
приёмка остаются unverified. Полный Codex Git-сценарий не подменяет их и не
подтверждает Claude CLI, OpenRouter API или OpenAI API. Подключение готовых
credentials и эти проверки выполняются отдельной задачей; критерии сохранены
в [M2_LIVE_GATE.md](M2_LIVE_GATE.md) и
[M2_CLAUDE_RUNTIME.md](M2_CLAUDE_RUNTIME.md).
